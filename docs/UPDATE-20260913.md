# 2026.09.13 更新与部署

接收端版本 **1.1.0**，Sysmon 配置 **thesis-sysmon-v1.1.0**。C# 采集器仍为 1.0，预处理仍为 1.1.0。本文件描述这次修改，完整日常命令见项目根目录 README。

## 1. 进度文件故障不再直接终止接收

旧接收器在 `status.json.tmp` 替换 `status.json` 时遇到 Windows 访问拒绝，会退出接收循环，产生 incomplete 和 missing_end_frame。现在：

- `status.json` 属于辅助进度文件。创建临时文件、写入或替换产生的 `OSError` 被记录为运行告警，不添加到传输 `problems`，也不阻止 XML 接收、STOP、排空和最终保存。
- 状态写入每次只尝试一次，通常每 0.5 秒刷新；状态转换时也尝试刷新。失败后等下一次更新重试，不在接收热路径里反复等待文件锁。控制台第一次告警后最多每 60 秒再提示一次。
- 最终 metadata 新增 `receiver_version` 和 `status_updates`。后者包括 `write_failures`、`last_error`、`last_failure_utc`、`last_success_utc`。最后一次终态进度写入若失败，也会更新最终 metadata 中的失败计数；`last_success_utc` 主要反映结果提交前的最后成功刷新。
- `problems`、最终计数、队列丢弃、订阅错误、END、XML 和 SHA256 的原有完整性判定仍保留。XML/哈希/最终 metadata 保存失败仍会报错，不能标成正常完成。关键 JSON 替换只对 Windows 错误 5/32/33 做最多 4 次尝试，等待总计 0.175 秒；耗尽后继续抛出错误。
- PowerShell 使用允许原子替换的共享读方式读取进度文件。暂时读不到时继续轮询；终态判定可直接发现 metadata 提交，不依赖最后一次 status 更新。启动样本前仍必须读到当前运行、最近 5 秒内的 armed 状态；无法确认就中止启动，不凭过期进度推测就绪。

例如，`status=complete`、`transport_complete=true`、`problems=[]`、`status_updates.write_failures=3`，表示传输完整性检查通过，但有三次辅助进度写入失败；不代表丢了三条事件。若 `guest_final_stats.dropped>0`，仍是不完整采集。若进度文件始终不可用，自动控制器可能因无法确认 READY 而停止；手动 immediate 接收器自身可以继续采集。

## 2. 注册表规则的范围和代价

事件 1、5、11、26 仍使用空 exclude，保留所有被 Sysmon 记录的进程创建、退出、文件创建/覆盖及删除事件，不按样本名、家族、文档后缀或正常程序进行过滤。23 仍关闭，避免复制被删除文件；事件 11/26 并不覆盖全部文件读写，也不能证明文件已经加密。

注册表 12–14 从全量变更改为以下统一范围：

| 保留范围 | 研究用途 |
|---|---|
| Run/RunOnce、Winlogon、IFEO、SilentProcessExit、登录脚本、启动文件夹注册表设置 | 启动、持久化和进程执行上下文 |
| Services、SafeBoot、Lsa、Session Manager、Terminal Server、任务缓存 | 服务/启动/登录和计划任务相关变更 |
| Policies、Defender、Security Center | 安全及系统策略变更 |
| 系统/企业证书和 WinTrust | 信任设置变更；其中仅排除下面的自身建键噪声 |
| HKCR、Software\Classes、HKU\SID_Classes、FileExts、RegisteredApplications | 文件关联、扩展名和 COM 注册上下文，包括正常软件行为 |
| RenameKey / RenameValue | 即使不在上面范围，也保留可见的重命名事件 |

自噪声排除使用明确的 AND 规则：Image 必须是 `C:\Windows\Sysmon64.exe` 或 `C:\Windows\Sysmon.exe`，EventType 必须是 `CreateKey`，TargetObject 必须属于 `SystemCertificates\Disallowed`、`EnterpriseCertificates\Disallowed` 或 `WinTrust\Trust Providers\Software Publishing` 对应范围。三个条件同时满足才排除。

没有按 `*sysmon*` 名字模糊排除，也没有整体排除 SYSTEM、PowerShell、reg.exe、Windows 进程或所有 Sysmon 行为。同一证书位置的值修改和删除仍在范围内；其他程序创建这些键也仍在范围内。若你的 Sysmon 实际服务 Image 使用其他安装路径，需要先核对实际事件，不能认为该排除自动适用于所有安装路径。

这是减少采集量的明确取舍：普通软件偏好、最近打开记录，以及范围外的自定义恶意注册表标记可能不再被采到。**范围外记录不是被认定为良性；被保留的记录也不是恶意标签。** 两类软件必须使用同一配置，规则名、样本路径和家族不能作为模型答案特征。宽范围的文件事件本身仍可能产生高峰，无法承诺任意样本零丢失或固定文件大小。

6/7/10 沿用原 default+ 的筛选；其他事件类型与 v1.0 相同。没有按本次四个样本的 SHA256 或已知恶意扩展名定制规则。

配置过滤语义和事件含义依据 [Microsoft Sysmon 官方文档](https://learn.microsoft.com/en-us/sysinternals/downloads/sysmon)。安装继续使用 `-i XML`，更新继续使用 `-c XML`，无需运行生成器。生成器、`registry_policy.py` 和固定上游文件用于离线复现。

## 4. 如何更新现有环境

1. 等当前采集结束，关闭旧接收进程。备份物理机 `D:\SysmonRealtime` 的代码文件；原始日志目录保留。
2. 将新包中的 `SysmonRealtime` 内容覆盖到 `D:\SysmonRealtime`。至少应同时更新 `host/receiver.py`、`host/storage.py`、`host/process_helpers.ps1`、`host/run_mal_realtime.ps1`，并同步 sysmon、tools 和文档。不要把目录套成 `D:\SysmonRealtime\SysmonRealtime`。
3. 在健康虚拟机中，将新包 `sysmon` 和 `tools` 复制到 `C:\SysmonRealtime` 对应目录。C# 源码/EXE 未修改，不需要重装采集计划任务。
4. 虚拟机管理员 PowerShell 执行以下命令。示例采用原来已经安装的 `C:\Sysmon\Sysmon64.exe`；如果你的文件名或路径不同，替换为实际路径。无需为了这次改规则升级 Sysmon 二进制。

```powershell
$sysmon = 'C:\Sysmon\Sysmon64.exe'
$config = 'C:\SysmonRealtime\sysmon\sysmonconfig-export.xml'
$expected = '4a5c21aab60b528e3487452a82cf358c8cc58e4cdccc39741cbbed093f840243'
if ((Get-FileHash -LiteralPath $config -Algorithm SHA256).Hash.ToLowerInvariant() -ne $expected) {
    throw 'Unexpected Sysmon config SHA256'
}
& $sysmon -c $config
if ($LASTEXITCODE -ne 0) { throw 'Sysmon config update failed' }
& $sysmon -c
& 'C:\SysmonRealtime\tools\Test-ResearchTelemetry.ps1'
```

自检注册表位置改为 HKCU\Software\Classes 下随机测试键，以匹配新的实际采集范围；没有专门放行测试进程。自检只改变并清理自己的测试键和文件。八项检查应全部通过，另需在一次主机无害试采中核对同一 smoke 标记。

5. 结束测试会话，正常关闭健康虚拟机，保存新的关机快照，例如 `SysmonResearch_v1_1`。恢复旧快照会撤销虚拟机内的新配置；这是部署步骤，不是脚本自动替换了你的 `Normal` 快照。关机快照也用于重新验证此前的事件 3/22 时间异常。
6. 新规则使用新的输出根目录。自动采集时修改现有 `$options` 的以下项，然后仍运行原入口；其他参数和样本路径不变。正常软件继续使用 `immediate`，将 `--output` 换成新的正常批次目录。

```powershell
$options.SnapshotName = 'SysmonResearch_v1_1'
$options.OutputRoot = 'D:\SysmonLogs\thesis-v1_1-batch01'
.\host\run_mal_realtime.ps1 @options
# 上面的 $options 需要先按主 README 的完整示例定义。
# 正常软件对应 --output D:\SysmonBenignLogs\thesis-v1_1-batch01
```

自动跳过规则仍不比较 Sysmon 配置或快照指纹，因此必须使用新批次目录。每批按主 README 保存配置 XML 和 VERSIONS.json 副本。metadata 中的 `receiver_version` 只能证明接收端版本，不能证明虚拟机加载了新规则。

## 5. 试采通过后再扩大采集

先复测之前的四个样本和 Notepad++；另加入批量文件操作的正常场景检查高峰。核对 XML 能完整解析、SHA256 匹配、`status=complete`、`transport_complete=true`、`problems=[]`、最终 `observed=sent=event_count`、`dropped=watcher_errors=queued_events=0`，并检查实际窗口和启动证据。

`status_updates.write_failures` 不要求为零才能判定传输完整，但反复出现需要检查是否仍有旧版监视命令/程序占用进度文件。更新主 README 的终端 B 命令，使用共享读辅助函数。

本次修改没有直接修复或隐藏事件 3/22 的时间异常，也没有扩大或改变 C# 队列。冷启动后仍需检查两个事件时间源；不能用新规则减少日志条数来证明时间问题已经解决。完整日志仍不等于加密成功或家族标签正确。

自动验证的范围和结果见 `../INTEGRATION_CHECKS.md`。真实 VMware 串口吞吐和虚拟机 Sysmon 加载需按上述步骤确认，本包没有操作你的虚拟机、部署目录或原日志。
